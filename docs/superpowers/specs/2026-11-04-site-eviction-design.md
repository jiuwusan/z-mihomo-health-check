# 全局探查站点复核与临时隔离设计

用户已确认：全局共享并持久化；正常失败仅计数，连续失败满 20 次才复核；其他站点也失败时不隔离并冷却；仅被测站点异常时临时隔离；隔离站点低频复测成功后恢复，空池仍保留恢复通道。

## 方案

- 实例管理器持有共享 SitePool，常规探查及优先级恢复均从有效池随机选择。只统计常规探查的成功或出口失败；其他 URL、整组探查和恢复检查不额外累计。成功清零该 URL 的全局连续失败计数，控制错误、取消与旧配置结果不计入。
- 失败计数上限 20。第 20 次申请复核，之后同一 URL 至少冷却 30 分钟，冷却中只计数、不额外请求。复核在正常故障转移完成后执行，避免阻塞原切换。
- 复核使用当前出口，随机选择两个不同的有效备用 URL（仅剩一个时使用一个，没有备用时不隔离）。备用均成功才重测原 URL；原 URL 成功则清零，仍为出口失败则隔离。复核前后确认选择未变；任一步控制错误或取消都不隔离。其他实例同期成功会使旧复核失效。
- 隔离 URL 一小时后到期复测，所有实例合计每分钟最多复测一个，按最早到期优先。成功恢复并清零；出口失败再等一小时；控制错误或取消仅短暂退避。空池显示等待恢复且继续复测，不回填完整池。
- DATA_DIR/site-pool.json 原子保存计数、复核时间、隔离时间与复测时间，不受历史记录开关控制。启动校验并仅载入当前清单的 URL；新 URL 可用。成功保存后发布状态；保存失败记录错误且保留上次状态。损坏文件明确报错。
- 常规配置保存、实例停启删除不清空共享状态；不修改 sites.txt、实例配置结构或原故障切换规则。正在执行的旧请求不能自动恢复隔离项。互斥锁及版本令牌避免多实例重复复核、重复复测和过期结果提交。
- 状态接口与面板展示有效/总量/隔离数，记录隔离、恢复、冷却与写入失败事件。阈值和时间为固定值，首版不增加设置或管理弹窗。

## 局限与验证

单个出口的交叉检查仍不能证明全球可用性，临时隔离和复测用于控制误判的影响。单进程内多个实例共享；多个独立服务进程不共享内存锁，不应同时写同一 DATA_DIR。

验证 19/20 边界、清零、冷却、全局共享、重启、损坏与写失败、取消/旧配置、备用站点出口故障、健康备用加坏站点、并发成功使旧复核失效、隔离复测节流与到期、空池复活、恢复检查抽样，以及全部 Go/Web 回归、race、vet。
