# 优先级自动恢复实施计划

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不改变故障切换规则的前提下，可选地恢复到更高优先级国家分组。

**Architecture:** Go 控制器串行执行当前出口探查与恢复检查。恢复仅在当前出口健康时运行，逐个检查主分组原始 all 顺序中位于当前选择之前的成员，首个可用候选连续达标并通过切换前复验后回切。状态和计数留在内存，配置沿用现有 JSON 持久化。

**Tech Stack:** Go 标准库、原生 HTML/CSS/JavaScript、现有模拟 HTTP API 与 Playwright。

**Spec:** 用户已确认本聊天中的恢复方案：默认关闭、检查间隔 60 秒、连续成功 3 次、切换冷却 300 秒。面板展示候选、成功次数和剩余冷却；最近一小时历史记录候选变化及切换结果。

## Global Constraints

- 当前分支实施，不新增分支；不自动提交或推送。
- 故障切换优先，不受恢复冷却限制；正常成功清零出口失败计数。
- 每轮恢复随机一个站点，顺序测试高优先级成员，首个成功即停止，不整组测试。
- 候选变化、失败、API 错误、当前选择或顺序变化均重置连续计数；配置修改及重启后重新累计。
- 切换前复验候选，再读取当前选择和顺序，变化则取消；请求失败后读取实际选择确认结果。
- 初始化及检测到手动换组时开始冷却，控制器内切换时间在配置修改时保留，避免保存绕过冷却。
- 调度沿用串行及丢弃过期周期语义，恢复探查间隔为最低间隔，慢请求可能推迟后续探查。

## Review Focus

- 当前选择不在 all 中不得猜测顺序或回切。
- API 错误不计为候选健康或当前出口故障。
- 复验期间选择/顺序变化取消回切。
- 冷却不阻止故障切换，恢复关闭不产生额外请求。
- 老配置缺失字段继承默认值，API 部分更新保留恢复参数。
