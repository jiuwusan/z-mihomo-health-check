# 多 Mihomo 实例实施计划

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** 一个容器管理多个独立 Mihomo，各自配置、探查、切换、恢复与历史。

**Architecture:** InstanceManager 管理多个现有 Controller/HistoryStore，每个实例独立生命周期，配置请求和停止互斥。实例注册表原子保存，所有实例使用随机安全 ID 的独立目录，不提供旧文件迁移。Web 面板切换实例，所有异步响应带实例代次，避免串配置或历史。

**Tech Stack:** Go 标准库、原生 HTML/CSS/JS、现有 Go/Node 测试和 Chrome Playwright。

**Spec:** 用户确认多个独立实例，各自探查、切换和记录。原有首次等待、恢复探查间隔、连续成功阈值及一小时历史分页/可选五分钟持久化均按实例独立保留。

## Global Constraints

- 当前 master 实施，不自动提交、推送，不读订阅凭据。
- 首次启动创建新实例注册表和随机 ID 的待配置实例；不读取旧根目录 config.json/history.json，不搬移或重写旧文件。
- 新增、重命名、删除实例；至少保留一个实例。新增默认停用且历史持久化关闭，不复制已有 secret。
- 删除停止任务并从注册表移除，磁盘文件保留备份，不自动清除；新实例永不复用旧 ID。
- /api/instances 管理列表；/api/instances/{id}/{config,status,events,groups} 操作指定实例。不提供旧版无实例 /api 路径。
- 实例名 1–80 字符，唯一，拒绝控制字符。注册表校验版本、重复/非法ID和名称，拒绝路径穿越。
- 注册表和各实例配置立即原子保存；历史按各自开关每5分钟保存，正常停止补写。坏API不阻塞其他实例；配置或开启持久化的历史文件损坏时启动失败，避免静默覆盖。

## Review Focus

- 添加/改名/删除保存失败不能改变内存注册表；磁盘故障不能泄露secret。
- 慢API不能阻塞其他实例，删除/关闭不能被并发保存重新启用。
- 切换实例时丢弃旧状态、旧分页、连接测试和保存响应。
- 浏览器未保存配置切换前提示，管理操作与配置保存不能串实例。
- 重启后名称、配置和启用持久化的有效历史均恢复，分页游标不串实例。
